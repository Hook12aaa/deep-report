# Depth Modes

Two depth modes only. Refuse to start without one of the two named explicitly.

## `smart-brevity`

Same information density as extreme-detail, simpler language, shorter paragraphs, no orphaned subordinate clauses.

- Paragraphs: 2–4 sentences.
- Sections: 1–2 paragraphs plus a takeaway.
- Headings: every H2 carries a one-line summary directly under it.
- Vocabulary: prefer the shorter, more concrete word.
- Whitespace: more.

Smart-brevity is not bullet points. Bullet points trade depth for scannability. Smart-brevity preserves depth and improves readability.

## `extreme-detail`

Full depth. Longer prose. More sub-sections. Aimed at the reader who wants the complete picture.

- Paragraphs: 4–8 sentences.
- Sections: 3–6 paragraphs plus worked examples.
- Headings: H2 every major beat, H3 for sub-arguments.
- Vocabulary: precise technical terms, defined on first use.
- Worked examples, derivations, and edge-case analysis included.

Extreme-detail is not padding. Every sentence carries information; the difference from smart-brevity is the count of facts and arguments per section, not the wordiness per fact.

## Comparison

| Aspect | smart-brevity | extreme-detail |
|---|---|---|
| Sentences per paragraph | 2–4 | 4–8 |
| Paragraphs per section | 1–2 | 3–6 |
| Worked examples | One per report, if useful | One or more per major beat |
| Edge cases | Named only | Explained and quantified |
| Reader profile | Skim-then-deepen | Read-in-order |
| Target page count (rule of thumb) | 6–12 | 20–40 |

## Asking the user

> Which depth mode? `smart-brevity` keeps the same information with simpler language and shorter paragraphs; `extreme-detail` adds worked examples, derivations, and edge-case analysis.

If the user names neither, ask again. Do not infer.
